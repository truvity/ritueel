A **root** is what outsiders trust without further proof. Other keys are trusted because it certifies or binds them.

## Keys from zero

This page assumes nothing. The other pages of Learn use five ideas without stopping to explain them, so they come first, each with one example.

**Key pair.** A key pair is two keys made together: a *private* key that one holder keeps secret, and a *public* key that anyone may have. What the private key signs, anyone with the public key can check. Example: a root key is a key pair. The private key stays in a card or a cloud service, and the public key goes to everyone who must check what the root signed.

**Signature.** A signature is made from some data and a private key. A signature proves that the key made it. It does not say whose key it is. Example: a project signs a release, and a user checks the signature with the public key the project published.

**Digest and fingerprint.** A digest is a short number made from data. The same data always gives the same digest, and changed data gives another one. Programs usually sign the digest and not the data, so a card or a cloud key signs what it is given and cannot show what the digest stands for. A fingerprint is the digest of a public key, which people compare to know that they hold the right key. Example: an OpenPGP primary key is known by its fingerprint of 40 hexadecimal characters.

**Certificate.** A certificate is a public key together with a name, signed by another key. The signature says: this key belongs to this name. Example: a root certificate carries the name of the root and is signed by the root's own key. The certificate of an intermediate is signed by the root.

**Symmetric key.** A symmetric key is one secret, not a pair: the same key locks and unlocks. The keys of a root are key pairs, not symmetric keys. Example: a passphrase that locks a file and unlocks it again is used like a symmetric key. The only symmetric key that Learn mentions is on the [KMS page](/learn/how-a-kms-key-works/): KMS rotates only symmetric keys by itself.

## Two places a root shows up

| | X.509 (certificates, TLS, code signing) | OpenPGP (signatures on software, mail, git) |
|---|---|---|
| The root has | A *root CA certificate* and its private key. | The *primary key* of an identity. |
| Outsiders trust it because | It is installed in their trust store: the operating system's, the browser's, or a file your company ships. | They hold its public key in a keyring, and they have checked the fingerprint some other way. |
| What it signs | Certificates of intermediate CAs (CAs that the root certifies and that do the everyday signing). | Certifications of identities and the bindings of subkeys. |
| Looks like | A file of a few hundred bytes of public data. | A fingerprint of 40 hexadecimal characters. |

In both worlds the root is a **public** thing and a **private** thing. The public part is given to everyone, because everyone needs it to verify. The private part is what this site is about.

## Why a root is special

Three facts make a root unlike any other key.

1. **Nobody above it vouches for it.** An intermediate that is stolen can be revoked by the root. A root that is stolen can be revoked by nobody except itself, or by a new root that outsiders are persuaded to install. Persuading them takes weeks, or years.
2. **It is trusted for everything below it.** Whoever holds the private key of a root can sign an intermediate, or a binding, that every client of that root will accept. The key does not know who is asking.
3. **It is used rarely.** A root signs a few certificates or bindings a year. That rarity is what lets you keep it somewhere safer, and less convenient, than any other key.

## What goes wrong

- **Lost.** The root key is gone, and nobody can sign under it again. Existing certificates keep working until they expire, and then everything has to move to a new root, which every client must learn to trust.
- **Stolen.** Someone else can sign things your clients accept, until the root is revoked and the revocation reaches the clients.
- **Used by mistake.** A person signs the wrong request, with a wrong lifetime or a wrong name. The signature is real, and cannot be taken back.
- **Expired unnoticed.** A root with a fixed end date runs out on a bad day.
