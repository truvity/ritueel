ritueel guides each use of a root key (the top key of your certificates, or your OpenPGP primary key) and keeps a record of it. A root is the key that others trust without further proof. A ceremony is the planned, recorded occasion on which a root is used. Below: the five ideas, then two real jobs drawn as comics. Jump to [sign an intermediate](#sign-an-intermediate) or [bind the subkeys](#bind-the-subkeys-of-your-card).

A plan is the sheet that fixes what will be signed; its digest is a short fingerprint of it. The offline system is a computer started from a USB stick, with no network. A key file is an encrypted file that holds a software key.

ritueel is in its design phase: the program does not exist yet. These pictures show how it is designed to work.

## Five ideas

<Figure name="ideas">

1. [One set of ceremonies](/how-it-works/#every-ceremony-has-six-steps) for a key file, root cards or a cloud key service: the steps are the same, the guarantees are not.
2. [Prefer a key that cannot be copied](/how-it-works/cards/): born on a card or in a cloud key service, not in a file. It may be used on your own workstation, under conditions that depend on the kind of key; a key in a file is used only in the offline system.
3. [One bundle](/how-it-works/bundle-and-stick/) is one trust domain: its roots, its history, its trust files and what is known about the cards. A company and a person keep two bundles.
4. [Requests in, answers out](/how-it-works/#sign-an-intermediate): other systems use files, and a plan or a request made in one place can travel by any channel and run in another.
5. [A defined workflow](/how-it-works/#every-ceremony-has-six-steps): ritueel says what is due, and every ceremony has the same six steps.

</Figure>

## Every ceremony has six steps

Every use of a root is a ceremony. Only step 4 uses the root.

## Sign an intermediate

A requester is a system that asks for a certificate, such as sluis (a system that issues certificates every day and holds intermediate keys). It needs a certificate for its intermediate key. A root that cannot be copied, on cards or in a cloud key service, may sign on your workstation ([record 0005](../decisions/0005-a-ceremony-and-where-it-runs.md)). The conditions:

- A touch for every signature. This is for a root on cards. A cloud key has no touch: for a cloud root the typed digest and the role session stand, and its audit trail records every signature.
- The number of signatures stated in the plan.
- No retry of a failed touch.
- A check against the plan on a second device.

The last three hold for both kinds. A key in a file is used only in the offline system, which stays available for any root ([the stick](/how-it-works/bundle-and-stick/)).

</Figure>

## Bind the subkeys of your card

ritueel binds the subkeys of your day-to-day card to your own OpenPGP primary, kept in a key file. A key file can be copied, so this ceremony runs in the offline system. Each subkey is its own ceremony.

<Figure name="bind-subkeys">
  A passkey on a root card opens the key file: decided, not yet proven.
</Figure>
