The program does not exist yet; the pictures show how ritueel is designed to work. The directory names on the stick are proposed.

## The bundle

A bundle holds everything ritueel knows about one trust domain: plain files, and never a private key in clear ([the layout](/reference/bundle/#the-layout)). It does hold the card secrets, sealed to your recipients. You write one file, `ritueel.yaml`; ritueel writes the rest, and a request sits with its answer in `requests/<name>/`.

<Figure name="bundle-folder">
  A bundle is one directory of plain files for one trust domain. Its history (see the [glossary](/glossary/)) is never changed afterwards.
</Figure>

The directories `history/` and `trust/<number>/` are decided ([record 0006](../decisions/0006-bundle-history-and-trust-files.md)). The names of the files inside them are proposed.

## The USB stick

A key file can be copied, so it is used only in the offline system, and the plan is carried there on a stick ([record 0005](../decisions/0005-a-ceremony-and-where-it-runs.md)). A key that cannot be copied, a root on cards or a cloud root, may run on your workstation and needs no stick. You may still choose the offline system for any root.

The stick holds vanilla AirgapOS and one extra partition for ritueel: several versions of ritueel, several bundles and the encrypted key files. When you prepare a plan online, ritueel refreshes its copy on the stick and the plan records its digest, so the run uses the version of the program that made the plan. A digest is a short fingerprint of a file.

<Figure name="usb-stick">
  Key files sit beside the bundles, not inside: a bundle is made to be copied and shared; a key file is the root itself, even though it is encrypted.
</Figure>

<Proposed>
  The directory names on the partition, and the plan member that records the digest, are proposals, not yet in a record; the label and the file system are open. That AirgapOS boots from such a stick and uses the extra partition is still to be proven on hardware.
</Proposed>
