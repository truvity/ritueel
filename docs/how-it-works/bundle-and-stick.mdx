Only `version` is built; the pictures show how ritueel is designed to work.

## The bundle

A bundle holds everything ritueel knows about one organisation or one person: plain files, and never a private key in clear ([the layout](/reference/bundle/#the-layout)). It does hold the card secrets, but encrypted to the recipients of the key file (the keys that open it). You write only the wanted files, such as `ritueel.yaml`. ritueel writes the history and the trust files. A request, from the requester, sits with its answer in `requests/<name>/`.

<Figure name="bundle-folder">
  A bundle: plain files for one organisation or one person. Key files are never inside. Tags: wanted, you write it; seen, a check read it; history ([glossary](/glossary/)), written once; request, with its answer.
</Figure>

The folders `history/` and `trust/` are decided ([record 0006](../decisions/0006-bundle-history-and-trust-files.md)).

## The USB stick

A key file can be copied, so it is used only in the offline system, and the plan is carried there on a stick ([record 0005](../decisions/0005-a-ceremony-and-where-it-runs.md)). A key that cannot be copied, a root on cards or a cloud root, may run on your workstation and needs no stick. A cloud root always runs there, because the offline system has no network; you may choose the offline system for a root on cards.

The stick holds vanilla AirgapOS and one extra partition for ritueel: several versions of ritueel, several bundles and the encrypted key files. When you prepare a plan online, ritueel refreshes its copy on the stick and the plan records the digest of the program (a short fingerprint of it), so the run uses the version of the program that made the plan.

<Figure name="usb-stick">
  Key files sit beside the bundles, not inside: a key file is the root itself, even though it is encrypted. The way back is a join: it adds the files the bundle lacks.
</Figure>
