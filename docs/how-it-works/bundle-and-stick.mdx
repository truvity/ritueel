Only `version` is built; the pictures show how ritueel is designed to work.

## The bundle

A bundle holds everything ritueel knows about one organisation or one person: plain files, and never a private key in clear ([the layout](/reference/bundle/#the-layout)). It does hold the card secrets, but encrypted to the recipients of the key file (the keys that open it). You write only the wanted files, such as `ritueel.yaml`. ritueel writes the history and the trust files. A request, from the requester, sits with its answer in `requests/<name>/`.

<Figure name="bundle-folder">
  A bundle: plain files for one organisation or one person. Key files are never inside. Tags: wanted, you write it; seen, a check read it; history ([glossary](/glossary/)), written once; request, with its answer.
</Figure>

The bundle's folder names and ceremony file names are decided ([record 0006](../decisions/0006-bundle-history-and-trust-files.md), rule 37).

## The USB stick

A key file can be copied, so it is used only in the offline system, where a stick carries the plan ([record 0005](../decisions/0005-a-ceremony-and-where-it-runs.md)). A key that cannot be copied may run on your workstation and needs no stick: a cloud root always does, because the offline system has no network; a root on cards may use either.

The stick holds vanilla AirgapOS and one extended partition: the files partition (several versions of ritueel, several bundles and the encrypted key files) and the trace area (no file system; the attempt and the journals while a ceremony runs; the files are made from it at its end). When you prepare a plan online, ritueel refreshes the files partition and the plan records the program's digest, so the run uses the version that made the plan.

<Figure name="usb-stick">
  Key files sit beside the bundles, not inside: a key file is the root itself, even though it is encrypted. The way back is a join: it adds the files the bundle lacks.
</Figure>
