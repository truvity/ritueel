*Design phase: these are the principles the design follows today. Each links to the record or page that decides it. Principles 1 to 9 and 11 carry the same numbers as in [sluis](https://sluis.id), a system that holds intermediates. Number 10 is each product's own principle, and 12 and 13 are ritueel's.*

## What ritueel is, and is not

- **Teaching first, then tools that simplify the rituals.** The mission is that ritueel helps one person or a small team keep a private root and an OpenPGP primary key for years without losing it, leaking it, misusing it or letting it expire. It teaches the model first, and its tools run each ceremony with the person deciding. See [ADR 0007](/decisions/0007-ritueel-teaches-and-its-tools-simplify-the-ceremonies/).
- **A command-line tool, a wizard on localhost, and documentation, not a network service.** It holds no online keys. See [ADR 0001](/decisions/0001-scope-roots-and-transitions-systems-like-sluis-hold-intermediates/).
- **It owns roots, root ceremonies and root transitions** for X.509, OpenPGP and SSH CA key lists, personal OpenPGP keys included. See [ADR 0001](/decisions/0001-scope-roots-and-transitions-systems-like-sluis-hold-intermediates/) and [ADR 0005](/decisions/0005-trust-products-the-root-list-the-ca-bundle-the-ssh-ca-key-list-and-the-trust-sequence/).
- **It never holds an intermediate's private key.** Systems like [sluis](https://sluis.id) hold intermediates, and meet ritueel only through the [hand-off contract](/reference/hand-off-contract/).
- **Its records are files the operator keeps:** ceremony records, root lists, and keyring packages that ritueel builds and the user's own pipeline publishes. See [ADR 0004](/decisions/0004-ceremonies-plan-confirm-reserve-sign-verify-record/#the-directory-and-the-records) and [ADR 0006](/decisions/0006-release-keys-and-the-keyring-package/).
- **One maintainer, no code yet, no independent review yet.** ritueel is maintained by one person with AI agents, has had no independent security review, and has no code: it is a design and a teaching site. [GOVERNANCE.md](https://github.com/truvity/ritueel/blob/main/GOVERNANCE.md) says how that changes.

## The principles

Each principle is marked **Shared** with sluis or **ritueel's own**.

1. **Every key is born in its store and never leaves it.** *Shared.* A transition makes a new key, and the old one vouches for it. For a software key held in a replicating store (1Password), [the store's own replication](/learn/key-stores/) is its backup; an encrypted file copied elsewhere is a second copy of the key and is handled as [ADR 0007](/decisions/0007-ritueel-teaches-and-its-tools-simplify-the-ceremonies/) says. ritueel never exports a key from a card or a KMS. Wrapped data keys in a backup are escrow of data, not of keys. See [ADR 0002](/decisions/0002-key-custody-every-key-is-born-in-its-store-two-root-cards-or-one-kms-root-and-a-replica/) and [Root and intermediate](/learn/root-and-intermediate/) and [Moving from one root to another](/learn/transitions/).
2. **Trust is layered, and redundancy answers loss, not compromise.** *Shared.* There are two root cards because a card cannot be copied, and one KMS root plus a replica because KMS can replicate its key. A compromise is answered by revocation and a transition. See [ADR 0002](/decisions/0002-key-custody-every-key-is-born-in-its-store-two-root-cards-or-one-kms-root-and-a-replica/#keys) and [Two roots in practice](/learn/two-roots/).
3. **Keys are shared and rotated by rule.** *Shared.* A key is shared only where audience, lifetime, revocation coupling and callers are all equal, as for the X.509 root key that also signs the root list. Renewal re-signs; key material is replaced on an event or at most every three years, and a transition makes a new key, never a copy. See [the slot map](/decisions/0003-key-stores-and-the-card-layer/#the-piv-store-and-the-root-cards) and [renewal and replacement](/decisions/0002-key-custody-every-key-is-born-in-its-store-two-root-cards-or-one-kms-root-and-a-replica/#validity-renewal-and-replacement).
4. **Verify; never trust a claim.** *Shared.* Attest what can be attested, re-read KMS keys and their policies from the service, and accept no copy of either. A check that cannot run is reported as not run, never as passed. See [What the tool checks](/tools/cli/#what-the-tool-checks) and [the proof file](/reference/hand-off-contract/#the-proof-file).
5. **Open standards, as their consumers implement them.** *Shared.* OpenPGP keys are version 4 while `gpg` has no version 6, and a revoked key leaves the keyring package because `gpgv` ignores revocations. See [ADR 0006](/decisions/0006-release-keys-and-the-keyring-package/#the-keys).
6. **A written contract and test vectors, not shared code; things are named for what they are.** *Shared.* The word is `intermediate`, not the name of a device. See the [hand-off contract](/reference/hand-off-contract/) and its [test vectors](/reference/hand-off-contract/#test-vectors).
7. **A person only where a person adds safety.** *Shared.* A touch on a card and a typed digest of the plan need a person; routine work reads public files only and is automated. A renewal over the same key is routine and is automated where the store allows it; a person is required to make a root, to change the root set, and to certify a new key. See [ADR 0004](/decisions/0004-ceremonies-plan-confirm-reserve-sign-verify-record/#six-steps-every-ceremony) and [What a ceremony is](/learn/ceremonies/).
8. **Nothing without a consumer.** *Shared.* A store, a command or an option arrives with its first real installation or caller. See the [roadmap](/roadmap/) and [how decisions are made](/contributing/decisions/).
9. **Measure, and date the measurement.** *Shared.* A claim about a tool, a card or a service carries the day it was measured. See [the research pages](/research/).
10. **Two roots are redundancy, not control.** *ritueel's own.* Any one active root signs alone, and ritueel never claims otherwise: a second card is not a spare, two cards are not two-person control, and a replica is not a second root. See [the accepted limit](/decisions/0002-key-custody-every-key-is-born-in-its-store-two-root-cards-or-one-kms-root-and-a-replica/#the-accepted-limit) and [Two roots in practice](/learn/two-roots/#the-limit-you-accept).
11. **Public by default, private where it protects.** *Shared.* The design, the reasons and the roads not taken are public; secrets and private deployment details are not. See [Public content and secrets](/contributing/public-content/).
12. **ritueel teaches first.** *ritueel's own.* Every ceremony is explained, every road not taken is recorded, and a guide walks through each transition. The tools exist to simplify the rituals, and the wizard is a second face of the same ceremony engine, not a second implementation. See [ADR 0007](/decisions/0007-ritueel-teaches-and-its-tools-simplify-the-ceremonies/) and [A lost root card](/guides/lost-root-card/).
13. **Succession is the holder's duty.** *ritueel's own.* A root that others rely on outlives its holder's attention only if a named second person can find the cards, the PINs, the ledger and the revocation material, and has run the restore check. That is an organisational duty, like renewing a domain; ritueel reminds, as a registrar does, and does not take it over. The reminder is `ritueel status`, which warns before anything expires and when the newest restore report is old. See [ADR 0002](/decisions/0002-key-custody-every-key-is-born-in-its-store-two-root-cards-or-one-kms-root-and-a-replica/#consequences), [the restore check](/reference/drill/#the-restore-check) and [when a drill is due](/reference/drill/#when-it-is-due).
