# Changelog

This file is written by hand, for the person who uses a release. It is not a list of commits; the history is in git.

## How it is kept

- A pull request that changes what a user notices adds a bullet under `## Unreleased`: a new command, a changed output, a new file format, a fix for a visible fault.
- The maintainer renames `## Unreleased` to the version and the date at release time, and starts a new `## Unreleased`.
- A breaking bullet starts with **Breaking:** and says what to do first.
- Pure refactors, tests, documentation and dependency bumps need no bullet.
- The file names no ticket of a private tracker, no real account and no person other than the maintainer.
- Versions are never reused. A mistake is fixed by the next version ([GOVERNANCE.md](GOVERNANCE.md)).

## Unreleased

- Nothing is released yet. The first docs, the scope decision and the roadmap are in `docs/`.
- The site has a demo of the local page, the browser view of a ritueel bundle, at `/demo/`: the real page over made-up data, with three example bundles (`acme`, `globex`, `personal`), a switch between them and five scenes for `acme`. It has four entries, To do, Inventory, History and Trust set, and writes nothing. Its commands follow the command reference. The program that serves it is not built.
- The Go module `ritueel.id/ritueel` and the first command, `ritueel version`, which prints the version and the commit of the build. With `--output json` it prints one JSON object, as the command reference says. The exit codes are those of the command reference, and a command line that is not valid exits with 2. The other commands are not built, except `verify root-list`, below.
- The command `ritueel verify root-list`: the host's side of the signed root list. It checks a list and its `.jws` against the list the host holds or its initial pins, and with `--ca-bundle` also a CA bundle, and it signs and writes nothing. It exits 0 when the list is accepted, 3 with the reason code when it is refused, and prints the digests of the files it read. Writing and signing a list is not built.
- The program is built as one static Linux executable, without cgo, and the build checks that the file has no interpreter and no shared library.
- The command `ritueel check history` walks the hash chain of a bundle's ceremony records and checks every file that a record lists against its digest. It prints one line for each finding on standard error, exits 3 when a finding fails and 0 for a clean history, and prints the end of the history and the count of ceremony records. It reads files only, writes nothing, and does not read the trace area of a stick.
- `ritueel check history` now reports a file inside a trust set that no ceremony record lists as the finding `file-unlisted` also when its name is one that a desktop system writes (`.DS_Store`, `Thumbs.db`, `desktop.ini`, or a name that starts with `._`). Before, such a regular file was only a notice. The command exits 3, and the person removes the file; ritueel deletes nothing. Outside a trust set these names stay a notice.
- The command `ritueel new DIR` makes a bundle folder with its starter wanted files, among them `ritueel.yaml`. It makes no key and touches no card. It refuses a folder that exists, a parent that is missing and a folder inside another bundle, with exit code 1 and nothing written. With `--test-root` it marks the roots as test roots. A write that fails in the middle names every folder and file that was already written and deletes none.
- The command `ritueel check request STEM [--delegation NAME]` runs checks 1 to 9 of the hand-off contract on one request of a bundle, prints the nine results, and signs and writes nothing. It exits 0 only for a request that the checker accepted, with one warning that the signature and the expiry of the trust set were not checked, and 3 with the reason code when a check refuses. A run in which a check did not run, such as one with no `--delegation`, exits 1 and is not a verdict. It cannot judge an `openpgp-subkey` request yet, and it accepts only a request with a software key.
- `ritueel check request` now gives the warning `trust-set-unchecked` in every run that prints the nine results, not only for an accepted request. A refused request (exit code 3) carries it, and a request that is not complete (exit code 1) carries it last, after the warnings that say which check did not run. Before, only an accepted request had it. A run that stops before it has nine results gives no such warning.
- `ritueel check request` judges an OpenPGP request: it reads the primaries from the keyring file of the newest trust set. It stops with exit code 1, neither accepted nor refused, when the root list pins primaries and the set has no keyring file, when the file is refused, and when the list pins no primary for an `openpgp-subkey` request. The warning `trust-set-unchecked` now says that the roots and the OpenPGP primaries were read from a trust set that was not checked.
- The command `ritueel apply --plan-only` finds what is wanted and not applied, shows the plan in words, writes the plan folder `history/<ceremony>/` with `plan.json` and exact copies of the wanted files, and prints the name of the ceremony and the path and digest of the plan. It plans the first `apply` of an x509 test root, makes no key and writes no attempt. `apply` without `--plan-only` and `apply PLAN` are not built yet: each prints one line, writes nothing and exits 1.
